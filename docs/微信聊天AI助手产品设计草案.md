# 微信聊天 AI 助手产品设计草案

日期：2026-05-19

## 当前方向

先不做“代替发微信”功能。

第一阶段只做：

- 获取本机微信聊天记录
- 白名单过滤
- 前端展示和搜索
- AI 总结、人物分析、关系分析、聊天建议
- 定时任务
- 实时提醒

这是正确收敛。发送微信风险高，且已经验证过坐标自动化存在误发风险，不应进入 MVP。

## 一句话产品

一个本机运行的微信聊天 AI 工作台：后台持续读取本机微信近期聊天记录，前端可查看、搜索、筛选白名单会话，并让 AI 对聊天内容做总结、人物分析、关系分析、回复建议和定时提醒。

## 目标用户

第一用户就是当前使用者本人。

典型场景：

- 微信消息太多，想知道哪些重要。
- 群聊信息密度高，想提取重点。
- 和某个人聊天时，想要上下文和回复建议。
- 每天固定时间想拿到今日聊天总结。
- 想跟踪特定人、特定群、特定关键词。

## 非目标

第一阶段不做：

- 自动发送微信消息
- 自动回复
- 批量导出所有聊天记录
- 对所有会话默认全量分析
- 语音转文字
- 图片 OCR
- 文件内容解析
- 多用户系统
- 云端同步
- 移动端 App

这些都可以后置。

## 已验证技术基础

基于前期验证，`wx-cli` 已能支持第一阶段核心数据读取：

- `wx sessions --json` 可读取最近会话
- `wx new-messages --json` 可读取增量新消息
- `wx history <CHAT> --json` 可读取历史记录
- `wx members <CHAT> --json` 可读取群成员
- `new-messages` 连续 5 条测试消息未漏读、未重复、顺序正确
- `new-messages` 是全局增量流，会混入不同会话的新消息

主要限制：

- `new-messages` 没有 `local_id`
- `history` 有 `local_id`
- 私聊 history 匹配规则不稳定
- 图片、语音、文件暂时只能作为事件记录

## 第一版产品结构

```text
wx-cli
  -> 后台采集服务
  -> SQLite 本地库
  -> AI 分析任务
  -> Web API
  -> 前端网页
```

## 后台服务

后台服务职责：

- 定时调用 `wx new-messages`
- 将新消息写入 SQLite
- 按需调用 `wx history` 补齐历史消息
- 维护会话表、消息表、白名单表、任务表、分析结果表
- 触发定时任务
- 触发实时提醒
- 提供前端 API

建议运行方式：

- 本地 Node.js 服务或 Python 服务
- 第一版优先本地运行，不做公网暴露
- 数据存储使用 SQLite

## 数据采集范围

前端可设置“获取多少天以内”的聊天记录。

后台行为：

- 读取最近 N 天的会话
- 对白名单会话调用 `wx history`
- 对新消息调用 `wx new-messages`
- 新消息如果不属于白名单，默认不入库或只记录极少元数据

建议默认值：

- 最近 7 天
- 只处理白名单
- 不默认分析公众号和折叠会话

## 白名单

白名单是 MVP 的关键安全边界。

第一版决策：

- 白名单由前端配置。
- 默认空白名单。
- 后台不默认采集和分析全部微信会话。
- 用户需要在前端从最近会话中主动添加白名单。

白名单支持：

- 指定群聊
- 指定一对一聊天
- 指定文件传输助手
- 可启用/停用

白名单字段：

- `chat_id`
- `chat_name`
- `chat_type`
- `enabled`
- `analysis_enabled`
- `realtime_enabled`
- `notes`

行为：

- 只有白名单会话才进入消息库
- 只有开启 `analysis_enabled` 的会话才进入 AI 分析
- 只有开启 `realtime_enabled` 的会话才触发实时建议

## 前端网页

第一版前端页面：

### 1. 首页仪表盘

展示：

- 今日新增消息数
- 白名单会话数
- 待处理提醒
- 今日总结入口
- 最近分析结果

### 2. 聊天记录

能力：

- 按会话查看消息
- 按时间筛选
- 按消息类型筛选
- 搜索关键词
- 只看某个发送人
- 查看原始消息

### 3. 白名单设置

能力：

- 从最近会话中添加白名单
- 开关分析
- 开关实时提醒
- 设置会话备注
- 设置默认分析范围

### 4. AI 分析

能力：

- 对某个会话生成总结
- 对某段时间生成总结
- 对某个人生成画像
- 分析关系和互动模式
- 生成聊天建议

### 5. 任务设置

能力：

- 创建定时总结任务
- 创建实时提醒任务
- 查看任务执行记录
- 查看失败原因

## AI 处理能力

### 总结内容

输入：

- 指定会话
- 指定时间范围
- 指定消息类型

输出：

- 重点内容
- 待办事项
- 重要链接
- 被提及的人和事
- 需要后续跟进的问题

### 分析人物

输入：

- 某个人在一个或多个会话中的消息

输出：

- 常聊主题
- 关注点
- 情绪倾向
- 沟通风格
- 可能需要跟进的事项

注意：

- 第一版应避免过度心理诊断。
- 输出应基于聊天证据，而不是武断判断。

### 分析关系

输入：

- 两个人或多个人的互动记录

输出：

- 互动频率
- 主要话题
- 谁经常发起沟通
- 是否有未回复事项
- 潜在合作机会或冲突点

### 聊天建议

输入：

- 最近聊天上下文
- 当前未回复消息
- 用户偏好

输出：

- 建议回复方向
- 2 到 3 个回复草稿
- 风险提醒
- 是否建议暂缓回复

第一版只生成建议，不自动发送。

## 定时任务

示例任务：

```text
每天 18:00 总结今日白名单聊天内容
```

任务字段：

- `name`
- `type`
- `schedule`
- `target_scope`
- `prompt_template`
- `enabled`
- `last_run_at`
- `last_status`

第一版任务类型：

- 每日总结
- 每周总结
- 指定会话总结
- 指定人总结

## 实时提醒

示例：

```text
对某个人，有新消息就提供聊天建议。
```

实时提醒字段：

- `target_chat`
- `target_sender`
- `trigger_type`
- `enabled`
- `cooldown_minutes`
- `prompt_template`

触发条件：

- 白名单会话出现新消息
- 指定人发消息
- 指定关键词出现
- 未回复超过一定时间

第一版建议：

- 先做“指定人新消息 -> 生成聊天建议”
- 加冷却时间，例如 5 分钟内只提醒一次
- 不自动打断，只在前端通知中心显示

## 搜索

第一版搜索范围：

- 消息正文

可选增强：

## MVP 建议

第一版只做 5 件事：

1. 白名单会话管理
2. 拉取最近 N 天白名单聊天记录
3. 前端展示和搜索聊天记录
4. 对白名单会话生成总结
5. 每天 18:00 生成一次今日总结

第二版再做：

- 人物分析
- 关系分析
- 实时聊天建议
- 通知中心

第三版再做：

- 更复杂任务编排
- 多模板 prompt
- 语音转文字
- 图片 OCR
- 回复草稿工作流

## 最大风险

### 1. 白名单设计不清

如果默认读取全部微信记录，隐私风险太大，数据量也会失控。

### 2. 私聊 history 不稳定

部分私聊无法直接通过 `sessions[].chat` 调用 `history`。第一版要允许“某些私聊只能从增量流开始积累”，不要承诺一开始就能回溯所有私聊。

### 3. AI 分析太泛

如果只是“总结一下”，价值会很弱。必须让任务具体，例如：

- 今天有哪些我必须回复？
- 哪些群聊出现了投资/项目/工作机会？
- 某个人最近在关注什么？
- 哪些事超过 24 小时没有跟进？

### 4. 实时提醒打扰

实时提醒容易变成噪音。第一版建议做成通知中心，不做系统级弹窗。

## 关键产品判断

这个产品的价值不在“读取微信记录”。

真正的价值在：

- 从混乱聊天中提取行动项
- 帮用户发现该跟进的人和事
- 降低群聊信息过载
- 在回复前提供上下文和建议

所以第一版不要贪多。

先让每天 18:00 的总结真正有用。

## 待确认问题

1. 每天 18:00 总结是总结全部白名单，还是按会话分别总结？
2. AI 分析结果是只存在本地，还是允许调用云端模型？
3. 是否需要在前端展示原始聊天全文？
4. 实时提醒是只显示在网页里，还是要系统通知？
