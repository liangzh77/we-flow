# 微信发送能力验证报告

日期：2026-05-19

## 目标

验证是否可以通过本机自动化能力向微信“文件传输助手”发送消息。

## 结论摘要

可以通过桌面 UI 自动化“发出微信消息”，但已经证明不能安全、稳定地指定发送目标。

2026-05-20 更新：本次探索导致测试消息被发到错误聊天会话，且账号收到微信官方警告。自动发送微信方向已终止，不再作为后续能力验证项。

最终决策：

1. 永久禁止自动发送微信消息。
2. 永久禁止 RPA/UI 自动化控制微信发送。
3. 永久禁止“用户确认后由程序代按发送”。
4. 只允许读取、分析、生成草稿和本地展示。

## 1. wx-cli 原生发送能力

命令：

```powershell
wx --help
```

结果：未发现发送消息相关命令。

公开命令包括：

- `init`
- `sessions`
- `history`
- `search`
- `contacts`
- `export`
- `unread`
- `members`
- `new-messages`
- `stats`
- `favorites`
- `attachments`
- `extract`
- `daemon`

结论：

- `wx-cli` 当前定位是读取、查询、导出本地微信数据。
- 没有原生 `send` / `reply` / `message` 发送命令。
- 发送微信不能依赖 `wx-cli` 直接完成。

## 2. wxautox4 验证

安装：

```powershell
pip install wxautox4
```

安装成功。

测试代码：

```python
from wxautox4 import WeChat
wx = WeChat()
```

结果：

```text
未授权设备，获取授权：https://plus.wxauto.org
```

结论：

- `wxautox4` 安装可行。
- 但当前设备未授权，无法直接使用。
- 不适合作为当前项目的无依赖开源发送方案。

## 3. wechat-pc-auto 验证

安装：

```powershell
pip install wechat-pc-auto
```

安装成功。

测试代码：

```python
from wechat_auto import WxAuto

wx = WxAuto()
wx.load_wechat()
wx.send_msg("we-flow-send-test ...", who="文件传输助手")
```

结果：

- 能激活微信窗口。
- 但窗口识别不稳定。
- 包内部曾误识别到 `Codex` 窗口。
- 对当前微信 4 窗口，无法找到会话列表和搜索框。

关键日志：

```text
通过标题找到微信窗口，ClassName = 'Chrome_WidgetWin_1'
未找到搜索框
未找到会话列表控件
```

结论：

- `wechat-pc-auto` 的思路是对的。
- 但在当前微信 4 / 当前窗口环境下不能稳定工作。
- 不能直接作为可靠发送方案。

## 4. 底层 UI 自动化验证

由于微信 4 的 UIA 控件树几乎不可见，只暴露极少子控件，因此尝试了坐标 + 键盘自动化。

执行动作：

1. 聚焦微信主窗口。
2. 点击左上搜索框预估坐标。
3. 粘贴 `文件传输助手`。
4. 回车。
5. 点击右侧输入区预估坐标。
6. 粘贴测试消息。
7. 回车发送。

测试消息：

```text
WEFLOW_SEND_TEST_20260519_201409
```

验证命令：

```powershell
wx new-messages -n 20 --json
wx sessions -n 12 --json
```

结果：消息确实被发出，但发到了错误会话。

实际发送目标：

```json
{
  "chat": "20054767941@chatroom",
  "chat_type": "group",
  "content": "WEFLOW_SEND_TEST_20260519_201409",
  "sender": "suzhongqian001",
  "time": "2026-05-19 20:14",
  "timestamp": 1779192851,
  "type": "文本",
  "username": "20054767941@chatroom"
}
```

结论：

- 坐标/键盘方式确实可以让微信发送消息。
- 但当前实现无法可靠保证目标会话。
- 本次误发到了一个群聊，而不是文件传输助手。
- 这是一个严重安全风险。

## 5. 风险判断

当前已证明：

- 微信桌面客户端可以被 UI 自动化控制发送消息。
- 自动发送不是技术上完全不可行。

但也证明：

- 如果没有可靠目标确认，自动发送很容易误发。
- 坐标法受窗口位置、搜索框焦点、当前会话、缩放、多屏环境影响很大。
- 不能把这种方式用于真实自动回复。
- 微信官方已经发出警告，继续探索会带来账号限制或封禁风险。

## 6. 推荐方案

自动发送方向终止。

后续只允许实现：

- 生成回复草稿
- 显示目标会话
- 显示待发送内容
- 用户自己手动复制、改写和发送
- 本地网页或桌面通知展示建议

明确禁止：

- 自动打开目标会话
- 自动搜索联系人或群聊
- 自动填入微信输入框
- 自动按 Enter 或点击发送
- “用户确认后由程序代发”
- 自动把建议发送到文件传输助手或任何微信会话

## 7. 下一步验证建议

不再继续验证发送能力。

下一步只做：

1. 只读读取微信消息。
2. 白名单过滤。
3. 本地存储和脱敏。
4. AI 摘要、分析、提醒和回复草稿。
5. 本地网页或桌面通知展示建议。

不得再新增任何发送微信的技术验证。
