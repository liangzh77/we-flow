# 微信发送能力验证报告

日期：2026-05-19

## 目标

验证是否可以通过本机自动化能力向微信“文件传输助手”发送消息。

## 结论摘要

可以通过桌面 UI 自动化“发出微信消息”，但当前还不能安全、稳定地指定发送给“文件传输助手”。

当前不建议进入自动发送阶段。

推荐阶段：

1. 先只生成回复草稿。
2. 再做“填入输入框但不发送”。
3. 最后才做“用户确认后发送”。

## 1. wx-cli 原生发送能力

命令：

```powershell
wx --help
```

结果：未发现发送消息相关命令。

公开命令包括：

- `init`
- `sessions`
- `history`
- `search`
- `contacts`
- `export`
- `unread`
- `members`
- `new-messages`
- `stats`
- `favorites`
- `attachments`
- `extract`
- `daemon`

结论：

- `wx-cli` 当前定位是读取、查询、导出本地微信数据。
- 没有原生 `send` / `reply` / `message` 发送命令。
- 发送微信不能依赖 `wx-cli` 直接完成。

## 2. wxautox4 验证

安装：

```powershell
pip install wxautox4
```

安装成功。

测试代码：

```python
from wxautox4 import WeChat
wx = WeChat()
```

结果：

```text
未授权设备，获取授权：https://plus.wxauto.org
```

结论：

- `wxautox4` 安装可行。
- 但当前设备未授权，无法直接使用。
- 不适合作为当前项目的无依赖开源发送方案。

## 3. wechat-pc-auto 验证

安装：

```powershell
pip install wechat-pc-auto
```

安装成功。

测试代码：

```python
from wechat_auto import WxAuto

wx = WxAuto()
wx.load_wechat()
wx.send_msg("we-flow-send-test ...", who="文件传输助手")
```

结果：

- 能激活微信窗口。
- 但窗口识别不稳定。
- 包内部曾误识别到 `Codex` 窗口。
- 对当前微信 4 窗口，无法找到会话列表和搜索框。

关键日志：

```text
通过标题找到微信窗口，ClassName = 'Chrome_WidgetWin_1'
未找到搜索框
未找到会话列表控件
```

结论：

- `wechat-pc-auto` 的思路是对的。
- 但在当前微信 4 / 当前窗口环境下不能稳定工作。
- 不能直接作为可靠发送方案。

## 4. 底层 UI 自动化验证

由于微信 4 的 UIA 控件树几乎不可见，只暴露极少子控件，因此尝试了坐标 + 键盘自动化。

执行动作：

1. 聚焦微信主窗口。
2. 点击左上搜索框预估坐标。
3. 粘贴 `文件传输助手`。
4. 回车。
5. 点击右侧输入区预估坐标。
6. 粘贴测试消息。
7. 回车发送。

测试消息：

```text
WEFLOW_SEND_TEST_20260519_201409
```

验证命令：

```powershell
wx new-messages -n 20 --json
wx sessions -n 12 --json
```

结果：消息确实被发出，但发到了错误会话。

实际发送目标：

```json
{
  "chat": "20054767941@chatroom",
  "chat_type": "group",
  "content": "WEFLOW_SEND_TEST_20260519_201409",
  "sender": "suzhongqian001",
  "time": "2026-05-19 20:14",
  "timestamp": 1779192851,
  "type": "文本",
  "username": "20054767941@chatroom"
}
```

结论：

- 坐标/键盘方式确实可以让微信发送消息。
- 但当前实现无法可靠保证目标会话。
- 本次误发到了一个群聊，而不是文件传输助手。
- 这是一个严重安全风险。

## 5. 风险判断

当前已证明：

- 微信桌面客户端可以被 UI 自动化控制发送消息。
- 自动发送不是技术上完全不可行。

但也证明：

- 如果没有可靠目标确认，自动发送很容易误发。
- 坐标法受窗口位置、搜索框焦点、当前会话、缩放、多屏环境影响很大。
- 不能把这种方式用于真实自动回复。

## 6. 推荐方案

第一阶段不要自动发送。

推荐先实现：

- 生成回复草稿
- 显示目标会话
- 显示待发送内容
- 用户确认后再复制到剪贴板

第二阶段可以实现：

- 打开目标会话
- 把草稿填入输入框
- 不按 Enter
- 等用户手动发送

第三阶段再考虑：

- 用户二次确认
- 检测当前会话标题
- 检测输入框内容
- 最终发送

## 7. 下一步验证建议

如果继续验证发送能力，建议换一种更安全的测试方式：

1. 用户手动打开微信桌面端的“文件传输助手”会话。
2. 程序只向当前输入框粘贴测试内容，不按 Enter。
3. 用户确认输入框里内容正确。
4. 再由用户手动发送，或明确授权程序按 Enter。

这样可以把风险从“误发到陌生群聊”降到“填错输入框但未发送”。

在没有可靠会话识别之前，不建议程序自动搜索联系人并发送。
