# we-flow 工作原则

日期：2026-05-20

## 1. 绝不做自动发送微信

从 2026-05-20 起，`we-flow` 明确禁止继续探索、实现或启用任何自动发送微信消息的能力。

背景：

- 2026-05-19 晚上的技术探索中，曾尝试多个 RPA/自动化类工具。
- 最后一次坐标和键盘自动化虽然触发了微信发送，但消息发到了错误的群聊，而不是预期的文件传输助手。
- 2026-05-20 收到微信官方警告，并需要完成学习和考试后才解禁。
- 自动发微信属于微信官方严令禁止的风险行为，不再作为产品能力、技术验证或后续路线。

工作约束：

- 不写自动发送微信消息的代码。
- 不安装、接入或测试用于自动发送微信的 RPA、UI 自动化、外挂、Hook、协议或插件。
- 不设计 AI 代替用户发送微信的流程。
- 不通过坐标点击、键盘模拟、剪贴板、窗口自动化等方式触发微信发送。
- 不把用户确认后自动按 Enter 发送作为折中方案。
- 任何回复能力都只能停留在生成草稿、展示建议、复制文本层面，最终发送必须由用户在微信客户端内手动完成。

允许范围：

- 读取本机微信聊天记录，用于用户本人授权下的本地整理和分析。
- 生成摘要、待办、提醒、回复建议和回复草稿。
- 将草稿展示在本地网页或复制到剪贴板。
- 做隐私、脱敏、白名单、本地存储和日志安全相关工作。

## 2. 清理自动发送类工具

已安装或曾用于探索的自动发送类插件、包和配置应卸载或移除。

当前处理记录：

- 2026-05-20 已执行 `py -m pip uninstall -y wxautox4 wechat-pc-auto wxauto wechat-auto wxauto3 wxauto4`；当前 Python 环境均返回未安装。
- 当前全局 npm 环境未找到 `@jackwener/wx-cli` 或 `@jackwener/opencli` 命令入口，`where.exe wx` / `where.exe opencli` 也未找到可执行文件。
- `C:\Users\liang\.opencli\external-clis.yaml` 不存在。
- `C:\Users\liang\.codex\plugins\cache` 中未发现微信、OpenCLI 或 RPA 相关插件目录。
- 若后续发现其他微信自动发送、RPA、UI 自动化、Browser Bridge 或 Hook 类工具，应优先卸载，并在文档中补充清理记录。

保留边界：

- 只读读取工具可以作为数据采集能力继续评估，但必须明确只读边界。
- 一旦某个工具提供或诱导微信自动发送能力，不接入、不测试、不保留。

## 3. 后续产品方向

`we-flow` 后续只做微信消息读取、AI 分析和回复草稿。

优先级：

1. 白名单会话读取。
2. 本地 SQLite 存储。
3. 聊天记录展示和搜索。
4. 每日总结、待办、提醒。
5. 回复建议和草稿。

明确不做：

- 自动发送微信。
- 自动回复微信。
- 批量群发。
- 模拟用户操作微信发送。
- 任何绕过微信官方限制或风控的能力。
